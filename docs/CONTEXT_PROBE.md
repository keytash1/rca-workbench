# Структурированный контекст: отдельный исследовательский инструмент

Статус: `SYNTHETIC_CONTRACT_ONLY / NOT_PROMOTED`. Это не включённый адаптер
Workbench, не источник для ML и не инструмент помощника. Нет утверждения,
что подключение к настоящему Loki или повышение качества RCA уже проверены.

## Проверяемая гипотеза

Похожие задержки и количества ошибок могут соответствовать разным механизмам.
Структурированная запись `PermissionDenied` и HTTP 403 даёт другую проверку,
чем `ConnectionRefused` и HTTP 503. Прототип сохраняет это различие и источник;
он не выбирает причину автоматически. Запись о релизе — утверждение источника
о событии, не доказательство причинной связи с инцидентом.

## Запуск оператором

Создайте локальный конфигурационный файл вне Git, например
`.rca-private/loki-probe.json`. Это пример, требующий ваших настоящих меток:

```json
{
  "source_id": "teaching",
  "url": "http://127.0.0.1:3100",
  "service_label": "service_name",
  "services": {"payment": "payment-v1"},
  "labels": {"environment": "local"}
}
```

```bash
.venv/bin/python tools/loki_context_probe.py \
  --config .rca-private/loki-probe.json --service payment \
  --start 1700000000 --end 1700000030
```

Интервал — прошедшее время Unix UTC, начало включается, конец исключается.
Для авторизации есть необязательное поле `token_env`: имя серверной переменной
с Bearer-токеном, не сам токен. Вне loopback авторизация требует HTTPS.
Источник задаёт доверенный оператор, не браузер и не LLM; сетевой доступ
процесса дополнительно ограничивается средствами окружения.

## Контракт и ограничения

- Один GET `query_range`, точные фиксированные метки, без произвольного LogQL.
- Не более часа, 100 записей, 256 KiB ответа, 8 KiB на строку; без пагинации,
  повторов и редиректов. Отдельный дочерний процесс ограничивает ожидание
  источника десятью секундами; при превышении завершается только этот процесс.
- Допустимы структурированные `error.type`, `exception.type`, `service.version`,
  ограниченный `event.name` и HTTP-код. Тело сообщения, прочие метки, URL,
  команды инъекции и поля `root_cause`/`fault_type` не выдаются.
- Фильтр полей не гарантирует обезличивание. Даже имя исключения или версия
  могут быть закрытыми. Результат остаётся локальным; автоматической отправки
  LLM, внешней публикации или импорта в расследование нет.
- Время записи Loki не объявляется истинным временем события. Время чтения
  хранится отдельно. ID и SHA-256 исходной строки связывают выбранные поля
  с записью; SHA-256 не даёт права раскрывать её содержимое.
- `available` означает пригодный ответ, не полное покрытие. При достижении
  лимита — `truncated`; пустой ответ не подтверждает здоровье сервиса.
  Retention, sampling, задержки доставки и полнота остаются неизвестными.
- Неструктурированные строки учитываются как пропущенные, не интерпретируются
  свободным текстом. Неверный scope, предупреждения сервера и ошибки источника
  закрываются явным `unavailable`, а не нормальным отсутствием ошибок.

Испытания используют искусственные ответы и локальный HTTP-имитатор, не Loki.
До включения в продукт нужны один настоящий источник, сверка записей и часов,
аудит потока на утечку контрольной разметки и небольшой заранее заданный
сравнительный опыт «те же данные с контекстом / без контекста». В контрольных
случаях нужны нерелевантное изменение, отсутствие записи и отказ источника.
При отсутствии полезного различия адаптер не продвигается в основной UI.
